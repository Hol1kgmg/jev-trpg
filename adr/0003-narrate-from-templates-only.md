# 描写をテンプレートの選択に限り、LLM に文章を書かせない

## Context and Problem Statement

プレイヤーが読むのは結果の描写である。ここを LLM に書かせるのが、この種のゲームでは最も素直な作りに見える。行動を渡して、情景を返してもらえばよい。

しかしこの作りは 3 つの性質を同時に失う。

第一に、**再現性**。同じ状態・同じ行動・同じ乱数でも文章が変わるため、ターン処理のテストが書けなくなる。Constitution IV は「LLM なしでテストできること」を要求している。

第二に、**秘密の保持**。描写を書かせるには、書くための材料（怪異の正体、クリア条件、未入手の手がかり）を渡す必要がある。渡した情報は、いくら指示しても文章に滲む。FR-003 の防衛線が「指示がうまく効くこと」に依存してしまう。

第三に、**レイテンシと可用性**。文章生成は判定より遅く、失敗したときに代わりに出すものがない。SC-004（90% のターンで 3 秒以内）と、Jev 不達でもターンが完結することの両方が危うくなる。

一方で、テンプレートだけで書くと表現の幅が落ちる。同じ文言の繰り返しに気づかれれば、それはそれで体験が壊れる。

## Decision

プレイヤーに表示されるすべての文字列は、リポジトリ内のテンプレートから選ぶ。LLM は文章を 1 文字も生成しない。

- テンプレートは `web/src/data/templates/` に置く。結果描写は `(EntityStage, Direction, Outcome)` で引き、書かれていない組み合わせは方向性ごとの汎用表に落とす
- 差し込めるのは `{item}` / `{epithet}` / `{clue}` の 3 つだけ。未指定のキーは空文字に落とす
- 選択に使う乱数は引数で受ける（`rng: Rng`）。テストでは固定値を渡して決定化する
- 手がかりの本文はテンプレートではなく `GameState.clues` が持ち、`{clue}` に差し込まれる
- シナリオは生成で選ばれるため、テンプレートは特定の主題に依存する語（観測所、改札など）を含めない

表現の幅は、テンプレートの本数と、段階（`EntityStage`）・方向性・結果段階・正気度による分岐で確保する。正気度が 3 以下のターンは幻覚描写を 1 文足す。

**Non-goals**

- テンプレートの文面を LLM に生成させて同梱することは禁じない。禁じるのは**実行時の生成**である
- 表現の多様性を数値目標にしない。テストプレイで繰り返しが気になった箇所に本数を足す

## Consequences

- Good, because ターン処理が純関数になり、Jev をモックせずにテストできる
- Good, because 秘密が描写経路に入らない。`narrate.ts` が受け取るのは `GameState` と選択結果だけで、クリア条件の全文を文章化する経路が存在しない
- Good, because Jev が落ちてもプレイヤーには通常と同じ形の描写が出る。劣化は `ambiguous` という結果段階としてだけ現れる
- Good, because 描写のレイテンシがゼロになる。3 秒の予算をまるごと判定に使える
- Bad, because 表現の幅がテンプレートの本数で頭打ちになる。同じ主題を続けて遊ぶと繰り返しに気づく
- Bad, because 主題を増やすたびに、その主題に固有の言い回しを書く手間が増える。汎用表に寄せるほど描写は薄くなる

## Implementation Plan

- **Affected paths**: `web/src/data/templates/`、`web/src/lib/game/narrate.ts`
- **Dependencies**: なし
- **Patterns to follow**:
  - 文字列の組み立ては `narrate.ts` に閉じる。Route Handler や画面で文章を作らない
  - テンプレートには特定シナリオ固有の語を書かない。固有の情報はプレースホルダーか `Clue` の本文で渡す
  - 乱数は引数で受ける。`Math.random()` をテンプレート選択の中で直接呼ばない
- **Patterns to avoid**:
  - LLM の応答文字列をそのまま、あるいは加工して画面に出す
  - 描写のためにクリア条件・怪異の正体・未入手の手がかりを Jev へ渡す

### Verification

- [x] 同じ状態・同じ `Judgment`・同じ rng で結果が一致する（`resolve.test.ts`）
- [x] メタ入力が専用テンプレートに分岐し、秘密を開示しない（`resolve.test.ts` / `meta.ts`）
- [ ] テストプレイ 10 回で、繰り返しが気になる箇所を洗い出す（SC-002 の計測と同時）

## Alternatives Considered

- **描写だけ LLM に書かせる（判定はコード）**: 秘密を渡さなければ描写が状況に噛み合わず、渡せば FR-003 が指示頼みになる。どちらに倒しても得がない
- **テンプレートを LLM に選ばせる**: 選択の再現性が失われ、呼び出しが 1 ターン 2 回になる（Constitution II に反する）
- **描写を LLM、失敗時だけテンプレート**: テンプレートを結局全部書くことになり、そのうえで非決定性とレイテンシを抱える
