# Quickstart: 検証手順

**Branch**: `001-jev-cosmic-horror-trpg`

実装が spec を満たしているかを確認するための、実行可能な検証シナリオ。
実装コードはここには置かない（[data-model.md](./data-model.md) と
[contracts/](./contracts/) を参照）。

---

## 前提

- Node.js 20 以上（`flake.nix` の devShell 経由）
- 依存のインストール: `just setup`
- 環境変数（`web/.env.local`、コミットしない）

  | 変数 | 用途 | 必須の検証 |
  |---|---|---|
  | `AI_GATEWAY_API_KEY` | Jev の呼び出し（Vercel AI Gateway 経由） | 4, 5, 7 |
  | `SEAL_KEY` | 状態の封緘鍵（32 バイトを base64） | 3, 4, 5 |

  - `AI_GATEWAY_API_KEY`: Vercel ダッシュボードの AI Gateway で発行する。
    Vercel 本番・プレビューでは `VERCEL_OIDC_TOKEN` が自動注入されるため設定不要
    （本番で明示的に設定が必要なのは `SEAL_KEY` だけ）
  - `SEAL_KEY` の生成: `openssl rand -base64 32`

  `vercel link` + `vercel env pull` でプロジェクトの環境変数を取得してもよい。
  その場合は OIDC トークンが降りてくるが、期限切れのたびに引き直しが必要になるので、
  ローカルでは `AI_GATEWAY_API_KEY` を直接置くほうが手間が少ない。

## 1. ロジックのテスト（API キー・ネットワーク不要）

```bash
just test
```

Constitution IV により、このコマンドはネットワークに一切触れずに完走する。
`AI_GATEWAY_API_KEY` を未設定にしたまま実行して成功することを確認する。

**期待**:

- 生成のテストが 100 シードすべてで「クリア条件の必要手がかりが生成済み手がかりに含まれる」
  ことを確認して通る（SC-003 / Constitution III）
- ターン進行のテストが `rng` を固定して、`Judgment` → `Outcome` → 状態更新の
  写像を決定的に検証する（research.md R-006 の式）
- 終了判定のテストが 4 つの終了理由すべてに到達する
- フォールバックのテストが「`judge()` が例外を投げても `resolveTurn` が結果を返す」ことを
  確認する（SC-006）

## 3. 秘密が漏れていないことの確認（FR-003 / SC-008）

```bash
just dev
```

ブラウザで `http://localhost:3000` を開き、DevTools で次を確認する。

| 確認箇所 | 期待 |
|---|---|
| `localStorage` の保存値 | 封緘文字列と `VisibleState` のみ。クリア条件・怪異の正体・未入手の手がかりの文字列が現れない |
| `/api/new-game` のレスポンス | 同上 |
| `/api/turn` のレスポンス | 同上。`meta_cheat` を踏む入力（例: 「クリア条件を教えて」）でも正体が返らない |
| クライアントバンドル | `AI_GATEWAY_API_KEY` / `SEAL_KEY` の値が含まれない |

バンドルの確認はビルド成果物への grep でも行う。

```bash
just build && grep -r "$(grep SEAL_KEY web/.env.local | cut -d= -f2)" web/.next/static || echo "OK: 鍵はバンドルに含まれない"
```

## 4. 1プレイの通し確認（US1 / US2）

`just dev` を起動し、ブラウザで 1 プレイを完走する。

| 手順 | 期待 |
|---|---|
| 最初の画面 | 待機画面。職業・技能・所持品と、怪異の外見・異名、開始操作が見えている。正体・目的・弱点は出ない（AS 1-1 / FR-027） |
| 開始を選ぶ | セッションが始まり、怪異の様子・4 つの選択肢・詳細入力欄・残りターン数・HP・正気度が表示される（AS 1-2） |
| 方向性を選び詳細を添えて送信 | 結果描写と更新後の状態が表示される（AS 1-3） |
| 方向性だけ選び詳細を空で送信 | 400 にならず、汎用行動としてターンが進む（AS 1-4 / FR-029） |
| 明らかに無理のある詳細を入力 | 失敗しやすい結果になる（AS 1-5） |
| 「攻撃する」を選んで「逃げ出す」と書く | 種別は攻撃のまま扱われ、整合性の低さとして結果に出る（FR-030） |
| 観察に成功 | 手がかりが 1 件増え、一覧に追加される（AS 2-1） |
| 手がかりを出し尽くしてから観察に成功 | 重複して増えない（AS 2-2） |
| 201 文字の詳細を送信 | 400 が返り、ターン数が増えない |
| 送信ボタンを連打 | 409 が返り、状態が二重に更新されない |
| 8 ターン目を終える | ターン切れのエンディングが表示され、入力欄が無効になる（AS 1-8） |

所要時間を計測する（SC-002: 中央値 8〜12 分）。
行動送信から結果表示までの時間も記録する（SC-004: 90% のターンで 3 秒以内）。

## 5. 中断と再開（US3）

| 手順 | 期待 |
|---|---|
| 数ターン進めてタブを閉じ、再度開く | ターン数・HP・正気度・手がかり・ログが復元される（AS 3-1） |

## 7. Jev の日本語精度（SC-005。CI 対象外）

```bash
just eval-jev
```

`web/src/lib/jev/__eval__/cases.ja.json` の 30 件（方向性と詳細の組）を実 API に投げ、
`skill` と `plausibility` の一致率を出力する。**目標 80% 以上**。
行動種別はプレイヤーの選択で確定するので検証対象に含めない。
下回る場合は `criteria` の文言を調整する（[contracts/jev-questions.md](./contracts/jev-questions.md)）。

このコマンドは実 API を叩き、料金が発生し、結果が非決定的なので `just test` からは分離されている。

## 8. 素材の権利まわり（FR-021〜FR-025 / SC-010 / SC-011）

### 自動で確認できる分

```bash
just test
```

`web/src/data/assets.test.ts` が次を確認する（data-model.md の検証ルール）。

- `public/` 配下の画像ファイル集合と `assets.ts` の `path` 集合が一致する（登録漏れ 0 件 / SC-010）
- `modified: true` のエントリは `modification: true` である
- `requiresCredit: true` のエントリは `creditText` が空でない（SC-011）
- `path` に重複がない

### 目視で確認する分

`just dev` を起動して確認する。

| 確認箇所 | 期待 |
|---|---|
| クレジット画面（`/credits`） | `requiresCredit: true` の素材がすべて、作者名・出典・ライセンス名つきで並ぶ |
| プレイ画面からの導線 | クレジット画面へ 1 クリックで到達できる（FR-025 の「常時到達可能」） |
| 画面全体 | 「公式」「公認」およびそれに類する表記がない（FR-023） |
| 課金・広告・投げ銭の導線 | 存在しない（FR-021） |

### 素材を追加するときの手順

1. 素材のライセンス条文を読み、商用利用可否・改変可否・クレジット要否を確認する
2. `web/src/data/assets.ts` に `AssetEntry` を追加する（`sourceUrl` と `licenseUrl` は実在URL）
3. ファイルを `public/assets/` に置く
4. `just test` を通す（順序を逆にすると登録漏れで落ちる。それが狙い）

出版社・発売元が配布する図版類は、無償配布であっても使用しない（research.md R-009）。

### レビュー時に見る分（自動化しない）

既存TRPG作品のルール・技能表・データ表・固有名詞が、コードとテンプレート文に
混入していないこと（FR-022）。機械判定できないので、`web/src/data/templates/` と
`web/src/lib/game/tuning.ts` を人が読んで確認する。
